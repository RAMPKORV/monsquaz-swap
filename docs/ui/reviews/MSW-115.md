# MSW-115 — UI review record

**Scope:** automatic backups, the backup history, the restore wizard, and the
single-writer guard in Settings.

## Captures

All captures use the deterministic demo data in `ui/src/data/demo.ts`. The
times show in the event timezone.

- `settings-backups-populated-*` — folder, writer lock, four real backups.
- `settings-backups-empty-*` — no folder and no backups.
- `settings-backups-loading-*` — skeleton rows with the same geometry.
- `settings-backups-error-*` — unreadable folder, `Error` status, `Retry`.
- `settings-backups-long-*` — long folder name and ten backups.
- `settings-backups-foreign-*` — another machine holds the writer lock.
- `settings-restore-list-*` — restore wizard with four complete backups.
- `settings-restore-empty-*` — no complete backup in the folder.
- `settings-restore-preview-*` — integrity check, old-data warning, typed
  `RESTORE` confirmation.
- `settings-restore-done-*` — restored event list and the token prompt.
- `settings-restore-error-*` — damaged backup refusal.
- `settings-purge-dialog-*` — typed `PURGE` confirmation.
- `settings-takeover-dialog-*` — typed `TAKE OVER` confirmation.

Dark and light themes are captured at 1280×800 and 1024×700 for the populated,
empty, restore list, restore preview, restore done, backup error, and restore
error states. Loading has dark 1280 and 1024. The long and foreign states add
light 1280. The restore empty, purge, and takeover states have dark 1280 and
1024.

## Gate

`scripts/design-check.sh` passes: `design: pass. 0 locked findings are covered
by the baseline.` The gate covers 1280×800, 1024×700, and 640×400, text
contrast, keyboard focus, and the CSS token policy.

## Review method

Three adversarial passes: visual design, UX and copy, and accessibility. The
harness did not allow fresh reviewer subagents in this execution. Re-run the
three waves with independent reviewers before merge.

## Wave 1 — visual design

Must-fixes found and resolved:

- The loading state used three plain bars and the card grew when the list
  arrived. **Fixed:** the skeleton now uses the real history row grid, two text
  bars, and a time bar.
- The old-backup warning and the destructive confirmation both used red text.
  **Fixed:** the age warning is an amber `warning` block with an alert icon;
  the destructive consequence stays red.
- The backup status said `Off` when no folder was selected. **Fixed:** it says
  `Not set up`; an unreadable folder says `Error`.

Checked and accepted:

- The card aligns to the settings grid at 1280 and 1024. At 1024 the history
  time stays on the right; below 640 it moves under the copy.
- Long folder names and long event names wrap without clipping.
- The action row wraps without horizontal scroll. The dialog stays inside the
  viewport at 1024×700.
- No nested cards, nested scrollbars, or more than one primary action.

## Wave 2 — UX and copy

Must-fixes found and resolved:

- The restore done state used `Later`, which did not say whether the wizard
  would close. **Fixed:** the button is `Close`.
- The purge dialog did not state that deletion is irreversible. **Fixed:** it
  says `This cannot be undone.`

Should-fixes found and resolved:

- The folder help said `The app writes here`. **Fixed:** it says `The app writes
  to the selected folder.`
- The restore wizard did not state which timezone the backup times use.
  **Fixed:** it names the event timezone.
- A failed status load still said `Select a backup folder`. **Fixed:** it says
  the app could not read the folder and offers `Retry`.

Checked and accepted:

- The empty state names the next action: choose a folder, then back up now.
- The damaged-backup error says what happened, that the current data did not
  change, and keeps the list open for another choice.
- Both destructive dialogs use a typed word and state the consequence.
- The single-writer message names the machine, says the bot stays off, and
  points to `Take over`.
- Copy follows ASD-STE100: short active sentences, no contractions or idioms.

## Wave 3 — accessibility

Must-fixes found and resolved:

- After the asynchronous restore preview opened, focus stayed on the close
  button. **Fixed:** focus moves to the first backup radio, then to the
  `RESTORE` input, then to `Add bot token` in the done state.

Verified:

- Tab stays inside the restore dialog for 12 presses. Escape closes the dialog
  and returns focus to the `Settings` navigation item.
- The page has one `h1` (`Settings`), a card `h2` (`Backups and restore`), and
  an `h3` (`Backup history`). The history list uses `aria-labelledby`.
- The section exposes `aria-busy` while it loads. Errors use `role="alert"`.
  Loading uses `role="status"`.
- Status pills use text plus icon plus color. No state depends on color alone.
- The design gate finds no contrast or focus-visible findings at 1280×800 and
  1024×700.
- The 640×400 render has no horizontal overflow, which covers the 200% zoom
  check. The global reduced-motion rule and `app--static` cover motion.
- A screen-reader application pass was not run; roles and names were checked in
  the DOM.

## Remaining findings

No must-fix remains. Every should-fix item above was fixed in this branch.
