# UI review — MSW-051 manual assignment editing

Review date: 2026-11-26. Build: MSW-051 worktree.

Screenshots: `docs/ui/screens/plan-edit-*.png`,
`plan-cell-focus-dark-1280.png`, and the planner context captures.

## Scope

- The host can select one assignment cell in the schedule planner before lock.
- The two people in that round swap tracks.
- The engine validates the whole plan, writes a new plan version with a new
  commitment, and records an audit entry.
- The dialog lists only valid candidates. A complete plan shows the no-swap
  state and offers Replace draft.

## Wave 1 — Visual design

| View | State | Severity | Problem | Resolution |
|---|---|---|---|---|
| Edit dialog | Default | should-fix | The first candidate was preselected, so Save could commit a person the host did not choose. | The select starts with “Choose a person”; Save is disabled until the host chooses. |
| Edit dialog | Default | should-fix | The copy said the people swap, but not which track each person receives. | The dialog states “After the swap: Ada takes S8G4H; Bo takes S2M8C.” |
| Matrix | Draft | should-fix | Editable cells looked identical to read-only cells. | They have a persistent dotted underline, a hover/focus treatment, and a 24 px target. |
| Edit dialog | No swap | should-fix | No capture of the no-valid-swap state. | `plan-edit-no-swap-dark-1280.png` and `-1024.png` show the message and Replace draft. |
| Edit dialog | Default focus | nit | Initial focus on Cancel competed with Save. | Focus moves to the New holder select when the candidates load. |
| Edit dialog | 40 people | nit | A native select with 39 options has no search. | Accepted for v1; a combobox is a later improvement. |
| Matrix | 1024 | nit | Fixed table layout compresses names. | Accepted; the matrix scrolls horizontally at smaller widths. |

No must-fix remained after the fixes. The reviewer re-checked and reported no
must-fix. Two evidence should-fix items were added: a selected-candidate
capture and a focused-cell capture.

## Wave 2 — UX and copy

| View | State | Severity | Problem | Resolution |
|---|---|---|---|---|
| Edit dialog | Complete plan | must-fix | The required no-valid-swap state was unreachable because the UI offered the track owner. | Candidates now come from the backend. The endpoint checks both swap directions, own tracks, repeats, readiness, and full plan coverage. |
| Edit dialog | Candidates | must-fix | The UI checked only whether the candidate had seen the target track. | The backend candidate list is the only source. The demo mode uses the same rule check. |
| Demo mode | Edit | must-fix | Demo edits skipped validation and could create an illegal plan. | Demo candidates and edits use the same own-track, repeat, and owner rules. |
| No-swap copy | Complete plan | must-fix | “Shorten the plan” promised an action that does not exist. | Removed. The dialog offers Replace draft. |
| Save error | Failure | must-fix | Raw engine messages showed participant IDs. | The host maps errors to display names and next steps. |
| Edit dialog | Default | should-fix | The result and the counterpart track were not visible. | Added the reciprocal line and the round/track summary. |
| Edit dialog | Default | should-fix | “New plan version and commitment” was not verifiable. | The action bar shows Plan vN. The audit records the version and commitment. The lock publication gap is MSW-056. |
| Edit dialog | Saving | should-fix | Save stayed labelled “Save change” while busy. | Save reads “Saving…” and announces the busy state. |
| Dialog | Complete plan | should-fix | The reason for no swap was imprecise. | It says no person in this round can take the track without breaking a rule. |

No must-fix remained after the fixes. The reviewer re-checked the five
must-fix items and reported no must-fix.

## Wave 3 — Accessibility

The first pass found no must-fix. The should-fix items were fixed:

| View | State | Severity | Problem | Resolution |
|---|---|---|---|---|
| Matrix | Draft | should-fix | Every cell was a tab stop; a dense plan had 320. | Roving tabindex: one cell in the tab order. Arrow keys move between cells. The container arrows enter at the first cell. |
| Edit dialog | Saving | should-fix | Focus dropped when Save was disabled during the save. | Save stays enabled and in the DOM, reads “Saving…”, and the handler guards the second click. |
| Edit dialog | Failure | should-fix | The inline alert and the toast announced the same error. | The App no longer toasts edit failures. The dialog alert is the only announcement. |
| Edit dialog | Selection | should-fix | The reciprocal track line was not announced. | It has `aria-live="polite"`. |
| Matrix | Draft | should-fix | The dotted underline was 1.7:1. | It uses `--faint` (above 3:1 for a UI indicator). |
| Matrix | All | nit | Help text said arrow keys worked while the container had focus. | It now explains the roving tabindex path. |

No must-fix remained. The reviewer re-checked the must-fix items and reported
no must-fix. The dialog, keyboard path, names, focus restore, contrast, 1024
width, and 200% zoom pass.

## Adversarial review

| Area | Severity | Problem | Resolution |
|---|---|---|---|
| Complete plan | must-fix | The owner could be selected and the no-swap state never appeared. | Backend candidates validate every swap; complete plans return an empty list. |
| Whole plan | must-fix | Validation checked duplicates but not per-round coverage. | It now requires every active ready person and active track in every round. |
| Concurrency | must-fix | A stale host intent could apply to a newer plan. | The host sends the expected version. A mismatch returns `PlanChanged`. |
| UI audit | must-fix | The UI could not show or verify the plan version. | Plan data includes the version and commitment. The action bar shows Plan vN. |
| Paused people | must-fix | A paused participant could receive a track and block the round. | Active and ready membership is required. |
| Start gate | should-fix | An incomplete plan could start. | `start_event` revalidates the plan. |
| Tests | should-fix | No stale, paused, incomplete, after-start, or complete-plan tests. | Added. Old versions, audit, commitment, and exhaustive single-cell outcomes are covered. |

The reviewer re-checked the five must-fix items and reported no must-fix with a
merge verdict.
