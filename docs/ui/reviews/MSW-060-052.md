## Scope

- Classic group events rotate participants one group forward at each phase.
- Tracks stay in their owner group. The seen ledger still applies.
- A phase that cannot fill inside its groups uses the global pool and reports
  a host warning.
- The planner shows group names, a group filter above the matrix, the group
  list, track-code disclosures, and the rotation phases.
- The participant redaction preview never shows groups, the fun score, the
  group filter, or a group-derived row highlight.

## Automated evidence

- `cargo test -p swap-core groups`: 9 pass, including rotation, fallback,
  determinism, and group-size validation.
- The engine test covers 10 people, 2 groups, 9 rounds, rotation for the first
  four phases, and full coverage.
- `pnpm --dir ui test`: 49 pass, including group filter, preview reset, and
  phase tests.
- `scripts/check.sh`: tracker, UI, design, and Rust pass.
- `scripts/design-check.sh`: 0 locked findings. The matrix covers 30 pages,
  including the group planner, filtered group state, and participant preview.

## Wave 1 — Visual design

The first pass found must-fix items in the evidence and the fold:

| Item | Severity | Problem | Resolution |
|---|---|---|---|
| Rotation below the fold | must-fix | The phase list sat below the fun score and group list. | Rotation now comes before the group list and the Groups card comes before Fun score. A compact phase summary above the matrix lists the round ranges at every width. |
| Filter below the fold at 1024 | must-fix | The group filter was in the stacked rail after the matrix. | The filter moved into the matrix header, above the table. |
| Duplicate full-page captures | must-fix | The light and dense files were identical full-page renders. | Exact 1280x800 and 1024x700 captures now come from `docs/ui/capture.sh`. Dark and light are distinct. |
| Group badge | should-fix | The row header read as one string. | The header shows the track code and a separate `Group A`/`Group B` label. |
| Pressed chip | should-fix | The active chip used color only. | The pressed chip is bold and has the accent border and fill. |
| Warning count | should-fix | "2 to review" did not open the warnings. | A "Review warnings" link jumps to the warnings card. |
| Edit dialog names | should-fix | Demo names used a numeric suffix in one view only. | Demo participant names are unique first names in all views. |

No must-fix remained after the re-capture.

## Wave 2 — UX and copy

| Item | Severity | Problem | Resolution |
|---|---|---|---|
| Demo matrix contradicted rotation | must-fix | The demo matrix was the old unrotated plan. | The demo now runs a client-side group matching with rotation, seen checks, and global fallback. The matrix, phases, and fallback labels agree. |
| Fallback state absent | must-fix | No capture showed a global-pool phase. | The 12-person demo uses fallback in phases 3 and 4. The phase list says "Global pool (fallback)" and a warning is available. |
| Filter leaked into preview | must-fix | A selected group survived the preview toggle and could tint rows. | The filter resets when the preview opens and the row class is gated on `!viewAsParticipant`. A UI test covers the reset. |
| Filter meaning | should-fix | "Filter" implied hidden rows, but all rows stay. | The control is labelled "Highlight tracks by owner group". The status says "Highlighting Group A · N tracks. Other tracks stay visible." |
| Fallback wording | should-fix | "Global pool" read as an event-wide choice. | It says "Global pool (fallback)" and the phase help explains the return to groups. |
| Rotation help | should-fix | The help did not define the direction or the seen rule. | It says phase 1 stays in the base group, later phases move one group forward, and no one receives a track twice. |
| Group tracks | should-fix | "6 tracks" was not actionable. | Each group has a "Track codes" disclosure with the codes. |
| Fallback copy | should-fix | The warning said "Groups return in the next phase" even when the next phase also fell back. | The warning says "Later phases try groups again" and uses the plural label. |
| Participant copy | should-fix | The participant preview inherited edit help. | It has preview-specific help and the scroller no longer blocks arrow scrolling. |

No must-fix remained after the fixes.

## Wave 3 — Accessibility

| Item | Severity | Problem | Resolution |
|---|---|---|---|
| Filtered row contrast | must-fix | Whole-row 45% opacity dropped text below 4.5:1. | Matching rows get an accent tint and inset bar. Text stays at full strength. |
| Chip target | should-fix | The chips were exactly 24 px high. | The group filter chips are 28 px high with 8 px gaps. |
| Pressed state | should-fix | The pressed chip was color only. | It is bold and uses the accent border and fill. |
| Live result count | should-fix | Filtering gave no programmatic result. | A polite status says "Highlighting Group A · N tracks." |
| Participant help | should-fix | Edit help appeared when no cells existed. | The preview has its own help and the scroller does not prevent arrow scrolling. |
| Locked plan help | should-fix | A committed host plan used the participant preview help. | A locked host plan has a read-only help string. |
| Status mount | nit | The polite status was mounted only while a group was selected. | The status stays mounted and updates its text. The text is empty outside the host view. |
| Phase semantics | should-fix | The phase list label sat on a generic div. | The list is a named section with an ordered list. |
| Empty aside | nit | The participant view kept an empty "Planner details" landmark. | The aside is not rendered in participant view. |

No must-fix remained. The automated gate passes contrast, focus, overflow,
clipping, and the locked scales.

## Verdict

No must-fix remains after the fixes and exact-viewport re-capture. MSW-060 and
MSW-052 are safe to merge. MSW-061 keeps the merge/re-split repair work.
