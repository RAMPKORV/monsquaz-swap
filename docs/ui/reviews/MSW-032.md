## Wave 1: visual design

| Finding | Severity | Resolution |
|---|---|---|
| The direct-message fallback was half-width and repeated the heading. | must-fix | It is now a full-width toggle with one label. |
| At 1024, the shared media rule pushed Token storage and Server to the right. | must-fix | `.bot-storage` is no longer in the flex rule; it stacks left-aligned. |
| The dialog footer cut the test-DM help and the remove section at 1024. | must-fix | The dialog is a flex column; the body scrolls and the footer stays fixed. Announcement and Reveal stay two-up. |
| Reconnect bot, Replace token, Add bot token, and Connect bot were competing labels. | should-fix | The header is the single connection action; Channels shows Map channels only when configured. |
| The settings grid jumped when the form became dirty. | should-fix | The status row always renders, and the header shows Save changes. |
| The empty state used a success check for a missing token. | should-fix | It uses a warning icon and one empty-state sentence. |

## Wave 2: UX and copy

| Finding | Severity | Resolution |
|---|---|---|
| Backend errors were technical and had no recovery step. | must-fix | Errors map to host sentences and MSW-BOT codes, next to the failing control, with field focus. |
| Errors could be below the fold after Save or Send test. | must-fix | Token, mapping, test, keychain, and remove errors render next to their controls. |
| No-server and one-channel states had no guidance. | must-fix | The dialog says to invite, refresh, or create a second text channel. |
| The Discord user id was undefined. | must-fix | The help gives the Developer Mode and Copy User ID steps; invalid ids fail inline. |
| After save, focus stayed on a disabled Save button and the next step was unclear. | must-fix | Save hides, focus moves to the test DM field, and the notice names the next step. |
| A saved connection had no production summary or token re-entry guidance. | must-fix | The dialog shows a read-only server/channel summary and says to paste the token to change it. |
| Keychain and session-only copy did not state the consequence. | must-fix | The copy says the bot stops at quit and the token must be entered again. |
| Remove used a two-click button with no consequence copy. | must-fix | An explicit confirm panel states the bot goes offline and Discord messages stay. |
| The first-run dialog had no portal or token-creation path. | must-fix | It has a Developer Portal link, an inline token guide, and a selectable invite URL if the browser fails. |
| Demo test DM said both sent and not sent. | should-fix | The demo says the message is a preview and is not sent. |

## Wave 3: accessibility

| Finding | Severity | Resolution |
|---|---|---|
| The 1180 media rule broke the Token storage and Server layout. | must-fix | Fixed with a left-aligned stack. |
| Disabling a focused async button dropped focus out of the dialog. | must-fix | Focus moves to the dialog intro; after the action it moves to the invalid field, keychain option, test field, or token field. |
| The light dialog rendered with dark tokens. | must-fix | The theme is set on the document element, so overlays inherit it. |
| Bot identity help was 4.10:1 at 11 px. | must-fix | It uses the raised faint token. |
| Errors had no `aria-invalid` or `aria-describedby`. | should-fix | Fields and selects mark invalid state and reference the error id. |
| Remove confirmation was not clearly announced or cancellable. | should-fix | It is a role=alert panel with Keep connection and Remove connection. |
| The disabled Save had no stated prerequisites. | should-fix | Visible save help is referenced by the Save button. |
| The identity live region wrapped buttons. | should-fix | Only the text copy is a live region. |
| The dirty form had no early submit control. | should-fix | The header Save changes button submits the form. |

## Round 2 verification

The visual review requested changes: duplicate Save actions in the dirty state,
an over-wide fallback description, and the saved dialog focusing the empty token
field. The duplicate savebar is removed, the description is capped, and a saved
dialog focuses the test-DM field.

The UX review requested changes: a no-mutual-guild test error was mapped to the
server mapping, the test section stayed visible while a new token was unsaved,
the invite fallback could disappear while its error remained, the zero-guild
refresh did not clear stale IDs, the session checkbox stayed editable after save,
and the demo error states were not realistic. Each is fixed, including
prefilled demo error states.

The accessibility review requested changes: saved-summary and confirmation help
contrast, mapping error focus targets, a keyboard-reachable invite fallback, and
one save surface. The contrast is raised, server/channel errors have distinct
targets, the fallback is a read-only focusable input, and the header is the only
save surface.

The security review requested changes: a locked keychain with a session could
report a successful removal while a keychain token survived; `BotSetupInput`
still derived `Debug`; and a second instance could clear a live session label.
The clear path now distinguishes a missing store from a locked store and keeps
the mapping for retry, the input no longer derives `Debug`, and the app uses the
single-instance plugin.

## Final verification

- Visual design: accepted. No must-fix remained after the dirty-state,
  saved-focus, and text-measure fixes.
- Accessibility: accepted. The saved-summary and confirmation contrast and the
  duplicate-channel error references were the last fixes.
- Security and code: accepted. The locked-keychain removal keeps the mapping
  for retry, `BotSetupInput` has no `Debug`, and the single-instance plugin is
  registered first.
- UX: accepted. The token-error demo now validates the three-part shape,
  clears identity and mapping, and disables Save; the screenshot matches the
  real failure state.

All review waves are closed with no must-fix findings. Evidence: 40
`swap-discord` tests, 29 without the live feature, 27 `monsquaz-swap` tests, 24
UI tests, strict clippy, and `scripts/check.sh`.
